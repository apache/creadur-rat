# Creadur RAT Migration Guide - Release 0.19

Release 0.19 is an intermediate release as we are working on big architectural changes within the 1.0.0 feature development.

## General

* [RAT-592](https://issues.apache.org/jira/browse/RAT-592) fixed the classification of BAT files/shell scripts, so that they are handled as standard files during RAT runs and need license headers.
* [RAT-582](https://issues.apache.org/jira/browse/RAT-582) completes this change for DTD files (`application/xml-dtd`). DTDs now need license headers as well. Python, Perl, and Node.js scripts with `#!/usr/bin/env ...` shebangs are also scanned, even when Tika classifies them as `application/x-sh`.

### SPDX license expressions

[RAT-583](https://issues.apache.org/jira/browse/RAT-583) changes SPDX detection from reading only the first identifier to parsing the complete expression after `SPDX-License-Identifier:`. This applies to all RAT interfaces.

Expressions support `AND`, `OR`, `WITH`, and parentheses. `WITH` binds to a single identifier, `AND` takes precedence over `OR`, and parentheses can override that precedence. Identifiers are case-sensitive and operators must be uppercase. Multiple spaces, tabs, and Unicode whitespace are accepted, including after the colon.

Approval now follows the expression instead of its first token. With the default approval configuration:

| SPDX expression | Result in 0.19 |
| --- | --- |
| `Apache-2.0 OR GPL-3.0-only` | Approved; the Apache alternative is reported. |
| `GPL-3.0-only OR Apache-2.0` | Approved; the Apache alternative is reported regardless of its position. |
| `Apache-2.0 AND GPL-3.0-only` | Unapproved; both required licenses are reported. |
| `(Apache-2.0 OR MIT)` | Approved. |

For `OR`, RAT selects an approved alternative when one exists. For `AND`, all required licenses must be approved. Separate SPDX tags are treated as additional requirements, not as alternatives. An independently detected license text is still reported even if an approved SPDX alternative exists.

When upgrading, check the following:

* **Keep each complete expression on one tag line.** Put explanatory prose on a separate line. Trailing prose, incomplete operators, and unbalanced parentheses are no longer silently ignored. Closing C-style (`*/`) and XML/HTML (`-->`) comment delimiters are supported.
* **Review changed approval verdicts.** Files previously approved because their first identifier was approved may now be unapproved when later `AND` requirements are not approved. Conversely, an approved `OR` alternative can now be recognized even when it is not the first identifier.
* **Configure identifiers explicitly.** An unknown required identifier is reported as an unknown, unapproved license. A known approved `OR` alternative can still satisfy the expression. License references and legacy `+` suffixes are parsed but must match configured SPDX names; they are not automatically mapped to another identifier.
* **Configure `WITH` combinations separately.** Approving a base license does not approve an exception automatically. For example, use `<spdx name="GPL-2.0-only WITH Classpath-exception-2.0" />` in a license definition and approve that definition explicitly. An unconfigured combination is reported as unknown.
