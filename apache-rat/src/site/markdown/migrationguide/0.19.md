# Creadur RAT Migration Guide - Release 0.19

Release 0.19 is an intermediate release as we are working on big architectural changes within the 1.0.0 feature development.

## General

* [RAT-592](https://issues.apache.org/jira/browse/RAT-592) fixed the classification of BAT files/shell scripts, so that they are handled as standard files during RAT runs and need license headers.
* [RAT-582](https://issues.apache.org/jira/browse/RAT-582) completes this change for DTD files (`application/xml-dtd`). DTDs now need license headers as well. Python, Perl, and Node.js scripts with `#!/usr/bin/env ...` shebangs are also scanned, even when Tika classifies them as `application/x-sh`.

### Adding license headers to Markdown and AsciiDoc

[RAT-517](https://issues.apache.org/jira/browse/RAT-517) improves license header insertion for documentation files:

* Markdown and AsciiDoc files keep their YAML, TOML or JSON front matter at the beginning of the file, so site generators such as Hugo can still read the metadata. Both formats share the same front matter handling; RAT inserts the license after the metadata using the appropriate comment syntax.
  * YAML starts with `---` and ends with `---` or `...`.
  * TOML uses `+++` to open and close the front matter.
  * JSON starts with an object (`{`) on the first line and ends at its matching `}`. Nested objects, arrays and escaped characters in strings are supported. The closing brace must be followed only by whitespace on that line; document content starts on a subsequent line.
  * RAT checks the front matter boundaries, not the validity of all metadata values. Unterminated blocks, mismatched JSON delimiters and unterminated JSON strings cause an error and leave the original file unchanged.
* Markdown files receive the license as an HTML comment (`<!-- ... -->`).
* AsciiDoc files (`.adoc`, `.asciidoc` and `.asc`) receive the license in a `////` block comment after any front matter and native document title and header metadata. Files without either kind of metadata receive the license at the beginning.
* Files without a recognized extension can also receive license headers when RAT detects a supported Markdown, AsciiDoc, XML or HTML content type.

These changes apply when you use RAT to add license headers; normal license checking is unchanged. No configuration changes are required.
